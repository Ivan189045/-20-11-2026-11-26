# Цветочный магазин «Флора»

Техническое задание на разработку интернет-магазина цветов с доставкой.

## 1. Назначение

Сайт для заказа букетов и цветочных композиций с доставкой по городу.
Целевая аудитория — частные покупатели (подарки, события) и корпоративные
клиенты (оформление мероприятий). Основная задача — дать пользователю
возможность выбрать букет, оплатить его онлайн и получить доставку
в выбранный интервал.

## 2. Функции

### 2.1. Для покупателя
- Каталог букетов с фильтрами: цена, повод (день рождения, свадьба…),
  состав (розы, тюльпаны…), размер, наличие.
- Карточка товара: фото (несколько ракурсов), состав, размер, цена,
  сроки доставки, отзывы.
- Корзина и оформление заказа без обязательной регистрации
  (гостевой заказ) и с регистрацией (история заказов).
- Выбор даты и интервала доставки; вариант «сегодня — экспресс».
- Онлайн-оплата: банковская карта, СБП.
- Отслеживание статуса заказа (собирается → в доставке → доставлен).
- Уведомления: SMS/e-mail о подтверждении и смене статуса.
- Загрузка фото доставленного букета («фото перед вручением»).

### 2.2. Для администратора (панель управления)
- Управление каталогом: товары, категории, цены, остатки, фото.
- Управление заказами: смена статусов, назначение флориста и курьера.
- Управление зонами и тарифами доставки, интервалами слотов.
- Отчёты: продажи за период, топ-товары, отмены.
- Управление промокодами и акциями.

## 3. Интерфейс

### Пользовательская часть
- Главная: подборки «Хиты», «Новинки», «Скоро доставим».
- Каталог с листалкой и фильтрами, сортировка по цене/популярности.
- Карточка товара, корзина, оформление заказа (3 шага максимум).
- Личный кабинет: заказы, избранное, повторить заказ.
- Адаптивная вёрстка: мобильные, планшеты, десктоп.
- Требования к скорости: первый рендер ≤ 2 с при 3G; Lighthouse ≥ 85.

### Панель администратора
- Таблицы заказов с фильтрами и быстрым поиском по номеру/телефону.
- Редактирование товаров через формы с загрузкой изображений.
- Роли: администратор, менеджер, флорист, курьер — разный доступ.

## 4. Данные

Основные сущности:
- **Товар** — название, категория, состав, размеры, фото, цена,
  остаток, флаг «доступен к заказу».
- **Заказ** — номер, товары, сумма, промокод, получатель
  (имя, телефон), адрес доставки, дата и интервал, статус,
  способ оплаты, комментарий.
- **Пользователь** — телефон, e-mail, адреса, история заказов.
- **Доставка** — зона, тариф, слоты, назначенный курьер.
- **Промокод** — код, тип скидки, срок действия, лимиты использования.

## 5. Реализация

- **Фронтенд:** React (Next.js), адаптивная вёрстка.
- **Бэкенд:** Python / FastAPI (или Node.js — по согласованию).
- **База данных:** PostgreSQL. Хранение изображений — S3-совместимое хранилище.
- **Платёжный шлюз:** по выбору заказчика (ЮKassa, Tinkoff и т. п.).
- **Уведомления:** SMS-шлюз + e-mail.
- **Хостинг:** облако, контейнеризация Docker, CI/CD.
- **Интеграции:** 1С (остатки и цены) — опция второго этапа.

Этапы:
1. Прототип и дизайн-макеты (1–2 недели).
2. Каталог, корзина, заказ без оплаты (2 недели).
3. Оплата, уведомления, личный кабинет (2 недели).
4. Админ-панель (2 недели).
5. Тестирование и запуск (1 неделя).

## 6. Приёмка

Работа принимается по критериям ниже. Каждый пункт должен быть
воспроизводим — приёмка идёт по демонстрации сценария.

- [ ] Пользователь находит букет через фильтры за ≤ 3 клика.
- [ ] Заказ оформляется без регистрации и с ней; оба сценария работают.
- [ ] Оплата проходит в тестовом режиме шлюза; статус заказа меняется автоматически.
- [ ] При смене статуса покупатель получает SMS/e-mail.
- [ ] Администратор может добавить товар, изменить цену, закрыть продажу при нуле на складе.
- [ ] Нельзя оформить доставку на дату/интервал, где нет свободных слотов.
- [ ] Отмена заказа покупателем работает по правилам (до сбора — бесплатно).
- [ ] Вёрстка корректна на 360, 768 и 1440 px; на мобильных нет горизонтального скролла.
- [ ] Данные пользователя хранятся в зашифрованном виде; пароли — только в виде хэша.
- [ ] Есть инструкция по развёртыванию проекта в две команды (`make up`).
- [ ] Все эндпоинты API покрыты автотестами (минимум — критические сценарии заказа).

## 7. Вне объёма первого этапа

- Корпоративный портал и счета для юрлиц.
- Интеграция с 1С, программа лояльности, подписки на цветы.
- Мобильное приложение.
